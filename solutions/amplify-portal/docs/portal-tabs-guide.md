**並べ替えと絞り込みが効く範囲**:

![絞り込み — 名前の部分一致で表示行を狭める](screenshots/portal-files-filter.png)

`ListObjectsV2` はキーの昇順と前方一致（プレフィックス）しか提供しません。並べ替える列も、名前の部分一致も、API 側には無い機能です。したがってどちらも**取得済みのページに対して**適用されます。

- 既定の「名前 昇順」は Access Point が返す順序そのものなので、この差は生じません
- 未取得のページが残っている状態でそれ以外の並び順や絞り込みを使うと、一覧の上に適用範囲の注記が出ます。「さらに読み込む」で残りを取得すると注記の件数が追随します
- 注記が出ていない状態は「そのフォルダを全部読み込んでいる」ことを意味します

![適用範囲の注記 —「読み込み済みの 10 件に対して適用されます」](screenshots/portal-files-loaded-scope.png)

> 上の画面は注記を写すためにページサイズを一時的に 10 件へ下げて撮影しています。実際の既定値は 100 件で、注記の件数もそれに従います。

**コピー / 移動と、その前に立つガードレール**:

![コピー / 移動 — 保存先の表示と上書き拒否](screenshots/portal-files-copy-move.png)

移動先はツリーではなく入力です。ツリーのほうが快適ですが、入力でも後述の境界がバックエンド側で効くため、打ち間違いの最悪の結果は「拒否される」で、想定外の場所にファイルが置かれることではありません。実行前に**保存先のキーを表示**します（入力欄だけだと、ファイル名が付くのかどうかを読者が推測することになります）。

以下はすべて**バックエンド側**の判断です。ブラウザのダイアログは提案でしかなく、AppSync を直接呼ぶ経路はそれを見ません。

| ガードレール | 挙動 |
|------------|------|
| **テナント境界** | `GROUP_PATH_PREFIXES` の外側のキーは拒否。`storage-admin` は対象外。未設定なら制限なし |
| **上書き** | 移動先に何かあれば拒否。「置き換える」を押した再試行だけが上書きする |
| **`..` を含むキー** | 拒否。S3 キーは文字列なので `a/../b` は解決されず、前方一致の判定と人間の読みが食い違う |
| **キーの形** | 空・先頭の `/`・連続した `/`・制御文字・1024 バイト超を拒否 |
| **フォルダ** | 拒否。プレフィックス配下の全オブジェクトのコピーになり、途中で失敗すると中身が 2 か所に分かれる |
| **完全削除** | `.trash/` 配下のみ。かつ `acknowledgeIrreversible` が必須。つまり**ごみ箱に入れる → 消す**の 2 段階を踏まないと消せない |

> **テナント境界について**: この境界は以前フォルダー監視の受信箱にのみ適用されており、名前の変更・ごみ箱・復元・アップロードリンクは素通りでした。prefix 分離を設定している環境では、他チームのキーを直接指定すれば操作でき、他チームの prefix への署名付き PUT も発行できました。現在は**キーを取るすべての操作**と一覧が同じ境界を通ります。

> **完全削除に「元に戻す」が無い理由**: オブジェクトはバージョン管理されていないため、戻せる以前の状態が存在しません。だからこの操作だけは事前の確認に頼り、他の破壊的操作（名前の変更・ごみ箱・移動）は事後の「元に戻す」に頼ります。

**複数選択でフォルダを選べない理由**:

チェックボックスはファイル行にだけ付きます。ゴミ箱への移動は S3 Access Point 上の CopyObject + DeleteObject を 1 オブジェクトに対して行う実装なので、フォルダ（プレフィックス）を渡すと配下のファイルが取り残されます。フォルダ単位の削除には、プレフィックスを再帰的にたどるバックエンド側の action が必要です。

一括操作はファイルを 1 件ずつ順番に処理します。リストを受け取る action がバックエンドに無いため、選択件数と同じ回数の呼び出しが発生します。件数が多いときは進捗表示で完了を待ってください。

**行のその他の操作（⋮）**:

![⋮ を開いた状態 — 共有リンク・タグ・名前の変更・ごみ箱](screenshots/portal-files-row-menu.png)

行に常時表示するのはチェックボックス・お気に入り・プレビューの 3 つで、残りは ⋮ の中です。以前は 1 行に 7 個の操作が並び、ファイル名を読む前にそれらを読み飛ばす必要がありました。

- ⋮ はホバー時ではなく常に表示します。ホバーはタッチ画面に存在しない状態で、ポインタが乗っている間だけ存在する操作は Tab でも到達できません
- 読み上げ名にファイル名を含めます（「inspection_qc.json のその他の操作」）。同名のボタンが行数だけ並ぶと区別できません
- `role="menu"` は付けていません。中身は共有リンクのパネルとタグエディタを含み、`menu` ロールが約束する矢印キーでの項目移動を提供しないためです。名前付きの `group` として公開しています
- 一覧の末尾 2 行はパネルが下に収まらないため上向きに開きます

**キーボードとスクリーンリーダー**:

- フォルダを開く操作は行そのものではなく**フォルダ名のボタン**が持ちます。Tab で到達し、Enter または Space で開きます。行のどこをクリックしても開く動作はそのままです
- 行全体をボタンにすると、お気に入りの星がボタンの入れ子になり、行の読み上げが「お気に入りに追加 📁 ai-outputs - -」のように星のラベルから始まってしまいます。名前側に持たせることで、読み上げは開く対象のフォルダ名になります
- 一括操作ボタンは選択件数を含む読み上げ名（「選択した 3 件をゴミ箱へ移動」）を持ちます。各行にも「ゴミ箱へ移動」ボタンがあるため、名前だけでは区別できません

**Office プレビュー（新機能 2026-07-22）**:
- PDF: Presigned URL を `<iframe>` に渡すだけ（ブラウザ内蔵ビューアで表示）
- DOCX: `docx-preview` ライブラリでクライアントサイドレンダリング（レイアウト再現度 70-80%）
- XLSX/PPTX: 現時点非対応（ダウンロードリンク表示）。Phase 2 で Lambda Container Image 対応予定

**完了通知と「元に戻す」**:

![ごみ箱へ移動した通知と「元に戻す」](screenshots/portal-files-toast-undo.png)

名前の変更・ごみ箱への移動・復元・一括操作は、完了時に右下に通知を出します。以前は成功が無言で、一覧が再描画されたことだけが手がかりでした。

- 名前の変更とごみ箱への移動には**「元に戻す」**が付きます。どちらも逆向きの操作が存在するためです（名前の変更は逆方向の名前の変更、ごみ箱への移動は復元）
- 単一ファイルのごみ箱移動から**確認ダイアログを外しました**。ダイアログは事前に、毎回、まだ判断材料がない時点で尋ねます。「元に戻す」は事後に、間違いが見えている時点で答え、間違いがなければ何のコストもかかりません
- 一括操作の確認ダイアログは残しています。こちらが伝えるのは危険性ではなく**所要時間**です（選択件数と同じ回数の CopyObject + DeleteObject が走ります）
- 「元に戻す」が対象にするのは**実際に動いたファイルだけ**です。5 件中 3 件が成功した一括操作では、その 3 件だけを戻します
- バックエンドが移動先のキーを返さなかった場合、「元に戻す」は表示されません。押しても動かないボタンは無いほうがよいためです
- 通知は 12 秒（「元に戻す」付き）または 6 秒で自動的に閉じます。エラーは自動では閉じません

**名前変更 / ごみ箱の実体**:
- どちらも S3 Access Point 上の CopyObject + DeleteObject です。メタデータの書き換えではないため、大きなファイルでは時間がかかります
- ごみ箱は同一バケット内の `.trash/` プレフィックスです。別のストレージではないため、容量は解放されません
- CopyObject は IAM アクションではありません。実行ロールに必要なのは source の `s3:GetObject` と `s3:GetObjectTagging`、destination の `s3:PutObject` と `s3:PutObjectTagging`、および元を消すための `s3:DeleteObject` です。`s3:CopyObject` という記述は存在しないアクションで、何も許可しません（[ポータル CDK / 品質ゲートの罠](../../../docs/agent/portal-cdk-quality-gates.md) 参照）

**アップロードリンクの注意**:
- 発行した URL 自体が認証情報です。期限まで、URL を持つ誰でもそのキーに書き込めます
- UI が保存先キーと有効期限を併記するのはこのためです

**文書解析の適用範囲**:
- Textract / Comprehend はファイルの内容をマネージドサービスに送信します
- 規制フォルダー（`phi/`、`dicom/`、`pii/`、`hipaa-`、`protected-health-`）配下では拒否されます。判定は `src/utils/regulatedPath.ts` の 1 箇所に定義されています

**CONFIDENTIAL ガードレール**:
- `shared/ai_guardrails.py` のデータ分類ラベルが CONFIDENTIAL/CUI の場合、AI Q&A をブロック
- ブロック時はエラーメッセージで分類レベルと理由を表示

### フォルダー監視（Folder Watch）

管理設定で「フォルダー監視」を有効にしたときだけサイドバーに現れます（既定はオフ）。

| 機能 | 操作 |
|------|------|
| 監視の追加 | プレフィックスを入力 → 対象イベント（作成 / 更新 / 削除）を選択 → 監視を追加 |
| 監視の解除 | 監視対象テーブルの「解除」 |
| 受信箱 | 登録したプレフィックス配下のイベントを新しい順に表示 |
| 未構成の表示 | 通知テーブルが未接続の場合、推測せず「未構成」と表示 |

**トグルが管理設定にある理由**:
- ポータルはイベントの発行元ではありません。FPolicy サーバーまたは Transfer Family が EventBridge に発行している必要があります
- 有効化は「発行元が存在する」という管理者の宣言です。既定オンにすると、発行元のない環境では永久に空の受信箱を見せることになります

**境界の絞り込み順序**:
1. Cognito グループのパス境界（`GROUP_PATH_PREFIXES`）
2. 自分の監視対象プレフィックス

この順序は入れ替えられません。監視は自分のレコードなので `/` も登録できますが、グループ境界の外は見えません（`storage-admin` は境界を迂回）。単一テナント構成では全イベントが見えます。ファイル一覧と同じ境界です。

**受信箱を Lambda 経由で読む理由**:
- `FileNotification` は `allow.authenticated()` で、ブリッジ Lambda は owner を持たずに書き込みます
- 生成モデルクライアントから直読させると、任意の認証ユーザーが全パス・全ユーザー名・全クライアント IP を読めてしまいます

**経路**: FPolicy サーバー（または Transfer Family）→ EventBridge → 通知ブリッジ Lambda → `FileNotification` テーブル → ポータル。FPolicy 自体の構成は [event-driven/fpolicy パターン](../../event-driven/fpolicy/) を参照。

### AI Chat（ツール実行エージェント）

ファイルを対象に、ツールを呼びながら応答するエージェントです。素のチャットと、保存済みエージェント / チームの実行の両方に使います。

| 機能 | 説明 |
|------|------|
| モード選択 | 通常チャット / エージェントモード。管理設定でエージェントモードを無効化すると選択肢が消える |
| ツール | ファイル一覧、読み取り、検索、および承認要求。エージェント定義のツールは実在するツールとの積集合になる |
| アクション承認 | 変更を伴う操作はカードで提示され、ユーザーの承認まで実行されない |
| 保存済みエージェントの実行 | Agent Directory から起動すると、その定義（システムプロンプト + ツール）で実行される。実行中はバッジで定義名を表示し、モード選択は隠れる |
| チームの実行 | Multi-Agent Teams から起動。メンバー構成とロールを 1 ターンのスーパーバイザーとして実行する（並行エージェントではない） |

> 到達できないチームメンバーがいても実行は継続し、応答の `unavailableMembers` に名前が入ります。全員到達できない場合のみ実行を拒否します。

## Data Protection グループ

### Snapshots（+ Tamperproof Snapshot ロック）

![Snapshots fallback](screenshots/portal-snapshots-fallback.png)

ONTAP REST API 経由で Snapshot 一覧を取得。各 Snapshot から「Browse this version」ボタンで FlexClone + S3 AP を作成し、過去のファイル状態にアクセス。

**Tamperproof Snapshot（Snapshot Locking）**:
- 各 Snapshot に 🔐（ロック済み）/ 🔓（未ロック）状態を表示
- ロック済み Snapshot は `expiry_time` まで削除不可（管理者含む）
- 「🔒 Lock」ボタン → 保持期間（1-365 日）を指定してロック（storage-admin グループのみ）
- ONTAP REST API: `PATCH /api/storage/volumes/{uuid}/snapshots/{uuid}` に `expiry_time` を設定

**前提条件（Tamperproof 有効化）**:
- ボリュームで Snapshot Locking が有効であること: `volume modify -volume <vol> -snapshot-locking-enabled true`
- SnapLock ライセンスは不要（Snapshot Locking は SnapLock とは別機能）

**ONTAP 未接続時のフォールバック UI**: 白画面ではなく、接続手順付きの info パネルを表示。

### ARP/AI（ランサムウェア検知）

![ARP fallback](screenshots/portal-arp-status-fallback.png)

ONTAP REST API から以下をリアルタイム取得:

| 取得情報 | API | 表示内容 |
|---------|-----|---------|

## テーマ（ライト / ダーク / システム）

トップバーに ☀️ 🌙 🖥️ の 3 択トグルがある。2 状態のスイッチではなく 3 択にしているのは、
「システムに追従」が実在する答えだからである。2 状態だとどちらかを初期値に決めるしかなく、
一度も触らない利用者の半分にとってその初期値は誤りになる。

![ファイル一覧（ダークテーマ）](screenshots/portal-files-dark.png)

| 選択 | 挙動 | localStorage |
|------|------|--------------|
| ☀️ ライト | 常にライト | `portal-theme=light` |
| 🌙 ダーク | 常にダーク | `portal-theme=dark` |
| 🖥️ システム | OS の設定に追従。日没時に OS が切り替われば追従する | キーを削除 |

「システム」でキーを保存せず削除しているのは、キーが無い状態と「システムに追従」が
同じ状態であり、両方を持つと食い違う余地が生まれるためである。

### 実装: 値ではなく役割で対応付ける

配色は 32 個のトークンとして `:root` と `[data-theme="dark"]` に定義し、各ルールは
トークンを参照する。**値ではなく役割で対応付ける**のが要点で、`white` は `color` なら
`--color-text-inverse`、`background` なら `--color-surface` になる。値だけを一括置換すると
役割が反転して壊れる。

初回描画前に `index.html` のインラインスクリプトが `data-theme` を解決するので、
保存済みの選択が一瞬ライトで描かれてから切り替わる（FOUC）ことはない。CSS 側に
`@media (prefers-color-scheme: dark)` は**置いていない**。パレットを二重に持つと片方が
古くなり、誰も見ていないテーマが壊れる。

### ガードレール

`make drift` が 5 つのルールで検査する。上の 4 つは色を、5 つ目は表示文字列を見る。
共通しているのは**書いた本人には見えない**という性質である。ハードコードされた明るい色は
書いた人のテーマでは正しく、ダークテーマで開いた人にだけ白い板が見える。

| ルール | 検出対象 |
|--------|---------|
| `theme-literal` | スタイルシート内の色リテラル。上限 4（意図的な 4 件は行にコメントで理由を記載） |
| `inline-colour` | JSX の `style={{ }}` 内の色リテラル。上限なし（インラインは後から上書きできないため） |
| `undefined-token` | 定義されていないトークン名の参照。常にフォールバックへ落ちる、または宣言が破棄される |
| `theme-contrast` | 同一ルール内の文字色と背景色のコントラスト比を両テーマで検査（WCAG AA: 本文 4.5:1 / 大きい文字 3:1） |
| `locale-escaping` | ロケール文字列の過剰エスケープ。`\"` のつもりの `\\"` は画面にバックスラッシュを出す |

`theme-contrast` はトークン化しただけでは足りないことへの対策である。ダークテーマの
アクセント色は暗い背景から浮かせるために**明るく**する必要があり、その上に白文字
（`--color-text-inverse`）を載せると primary ボタン全体が 3.4:1、承認ボタンが 2.8:1 になる。
白い板ではないのでリテラル系のルールは全て満たしてしまう。
対策として `--color-on-primary` / `--color-on-success` / `--color-on-error` を用意した。
**塗りはテーマで反転しないが、その上の文字は反転する**という役割である。

同一ルール内の組み合わせだけを静的に検査する。別のセレクタから背景が来る場合はカスケードの
解決が必要でブラウザが要るため、そちらは実機の目視検査に回している。

> **ゲートを信用する前に、通してはいけない入力で落ちることを確認する。**
> `theme-literal` は当初、行頭に固定した正規表現だったため
> `.state-online { background: #dcfce7; }` のような 1 行ルールを見られず、201 件あるうち
> 5 件と報告していた。`inline-colour` が無かった間は AI エージェントのカード 6 枚が
> インラインの淡色を保持し、ダークテーマの明るい文字と重なってコントラスト 1.1:1 で
> 出荷されていた。いずれもリポジトリの全ゲートが緑のままだった。
> 検査そのもののテストは `scripts/tests/test_theme_literal_check.py` にある。

## モバイル対応

スマートフォンのブラウザで利用できる。専用アプリはなく、同じ URL を開く。

> **利用者向けの手順**は[ユーザーガイドの「4. スマートフォンで使う」](../../../docs/ja/portal-user-guide.md)
> にある。この節はブレークポイントと CSS 側の扱いを説明する。

> **テーマトグルの 🖥️ はデスクトップ表示の切り替えではない。** 「システムに合わせる」
> （OS の外観設定に追従）という 3 つ目の選択肢である。モバイル対応とは無関係。

<img src="screenshots/portal-files-mobile-dark.png" alt="ファイル一覧（iPhone 相当・390px・ダークテーマ）" width="330">

| 幅 | 挙動 |
|----|------|
| 769px 以上 | サイドバーは本文の左に並ぶ列。既定で開いている |
| 768px 以下 | サイドバーは本文の**上に重なるドロワー**。既定で閉じており、☰ で開く。セクションを選ぶと閉じる |
| 480px 以下 | トップバーは操作のみを残す（製品名は視覚的に隠すが h1 として DOM に残る、サインアウトはアイコンのみ、メールアドレスは非表示） |
| 768px 以下 | 一覧の「サイズ」「更新日時」列を省略。480px 以下では名前と操作のみ |

### 満たしている基準

- **横スクロールなし**（390px 幅・11 タブ・両テーマで確認）
- **入力欄は 16px 以上**。iOS Safari は 16px 未満のフィールドにフォーカスするとページを拡大し、拡大後はレイアウトが収まらなくなる
- **タップ領域は 44×44**（行のチェックボックス・お気に入り・プレビュー・⋮、ヘッダーの
  各ボタン、絞り込み欄、プレビューの閉じる/ダウンロード）。WCAG 2.2 の下限は
  SC 2.5.8 の 24×24（AA）だが、指で扱う主要操作は SC 2.5.5（AAA）の 44×44 に揃えている
- **ドロワーは暗幕付き**。開くと本文が暗くなり、暗幕のタップまたは Escape で閉じる。
  セクションを選んでも閉じる
- **画面回転に追従**。390×844 はドロワー、844×390 は列。回転すると配置が切り替わる
- **プレビューはボトムシート**（画面下から最大 70vh）。行に紐づく吹き出しではないので、
  一覧のスクロールで切れたり画面外に開いたりしない

> **行のチェックボックスは自前描画**。ネイティブのチェックボックスは padding を無視するため、
> 既定の外観のままでは当たり判定を箱より大きくできない。`appearance: none` で 44×44 の
> 領域に 22px の四角を描き、チェックは回転させたボーダーで引いている（トークン参照なので
> 両テーマで見える）。

### レスポンシブ指定を書くときの注意

**メディアクエリは詳細度を上げない。** `@media (max-width: 768px)` の中の規則は、
同じセレクタが後方にあれば負け、より詳細なセレクタがどこにあっても負ける。宣言は
残ったまま無視されるので、失敗が静かである。実際に 2 件同時に発生していた。

- `.portal-layout { grid-template-columns: minmax(0, 1fr) }` が 200 行前の
  `.portal-layout.sidebar-collapsed`（クラス 2 個）に負けた。モバイルの既定は
  collapsed なので、1 領域のテンプレートに対して 3 列のデスクトップ配置が適用され、
  トップバーが 40px 幅になった
- `.form-group label` の指定が 1,000 行後の同一セレクタに負けていた

**レスポンシブ指定は、それが上書きする規則の直後に置く。** `make drift` の
`dead-media-override` ルールがこれを機械的に検出する。

| ルール | 検出対象 |
|--------|---------|
| `dead-media-override` | `max-width` メディアクエリ内の宣言のうち、後方の同一セレクタまたはより詳細なセレクタに負けて適用されないもの。`!important` は両方向で考慮する |

## CDK 品質ゲート

このポータルは以下の品質ゲートで保護されています:

| ツール | チェック内容 |
|--------|------------|
| cdk-nag (AwsSolutionsChecks) | IAM 過剰権限、暗号化、ログ保持 |
| CDK ハーネステスト (47 assertions) | Lambda 数、ランタイム、環境変数 |

| floci 統合テスト (9 tests) | S3 ListObjectsV2 + Delimiter 動作 |

cdk-nag は既定で無効（opt-in）。見たいときだけ `CDK_NAG=1 npx ampx generate outputs` を実行する。CI には未統合。
