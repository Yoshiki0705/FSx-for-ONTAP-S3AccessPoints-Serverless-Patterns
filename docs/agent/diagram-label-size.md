# 図のラベルサイズの下限

`make drift` の一部として `scripts/check_diagram_fonts.py` が検査し、CI では
`validators.yml` が同じ検査を走らせる。数値はそのスクリプトに置いてあり、規範は
`~/.kiro/steering/global-document-readability.md`。図の再生成手順そのものは
[diagram-regeneration](diagram-regeneration.md)。

## 判定の基準

ラベルが表示される大きさは、画像が読者のカラム幅に収まるよう縮小された**後**の大きさで
決まる。したがって `fontSize` の値だけでは可読性を判定できず、キャンバスが広い図ほど同じ
`fontSize` でも小さく表示される。下限は 2 つあり、両方を満たす必要がある。

| 下限 | 値 | 塞いでいる抜け道 |
|---|---|---|
| 実効サイズ = `fontSize × min(1, 880 / 書き出し幅)` | **14px 以上** | エディタでは読めるが公開ページでは読めないラベル |
| ソースの `fontSize` | **16px 以上** | キャンバスを狭めて実効サイズだけ満たし、文字は小さいまま |

880px は GitHub / dev.to / はてなブログの本文カラム幅。幅は `pageWidth` ではなく書き出した
SVG の幅を使う（draw.io は内容にクロップして `--border` を足すので両者はずれる）。

| キャンバス幅 | 必要な `fontSize` |
|---|---|
| 880px 以下 | 16 |
| 1200px | 20 |
| 1400px | 23 |
| 1600px | 26 |
| 1716px | 28 |

## 収まらないときの手順

**キャンバスを広げると必要な `fontSize` が上がる。** 空きのあるキャンバスは無料ではない。
下限を満たしたまま収まらなくなったときは次の順で解決し、**縮小は選択肢に入らない**。

1. ラベルを 2 行に折る（最大 2 行。単語の途中で折らない）
2. 図内の補足ボックスを本文の表へ出す
3. キャンバスを 880px 側へ狭め、要素を縦に積む（縦方向は幅を争わない）
4. 図を分割する
5. 抽象化する（個々のリソースを役割単位にまとめる）

## 既存の負債

`diagram-font-debt.txt` に載っている 60 ファイルは検査器より前に作られたもので、下限を
満たしていない。**このファイルは減る方向にしか動かせない。** 未記載の違反は失敗し、記載されて
いるのに下限を満たすようになったファイルも失敗する（修正すると行が消える強制力になる）。

直すには先に決めることがある。**図内の補足ボックスを本文へ移すかどうか。** 図に残す場合、
補足の最長行がキャンバス幅を決め、キャンバスを広げると必要な `fontSize` がさらに上がる。
本文へ移す場合、残るのは再レイアウトだけになる。
