# 保持期間の満了後にデータを削除する仕組み — 設計

保持期間（SnapLock の WORM、Tamperproof Snapshot、S3 Object Lock）が満了したデータを削除する
仕組みの設計です。実装は段階的に進めており、この文書は**残っている判断を再導出しないため**に
決定事項と制約を記録します。手順の再検討は不要です。

関連: [Tamperproof Snapshot 設計](tamperproof-snapshot-design.md)、
[検証結果](../solutions/amplify-portal/docs/verification-results.md)

## 構成

| 役割 | 使うもの | 理由 |
|---|---|---|
| 起動 | EventBridge **Scheduler**（定期実行） | **満了イベントは存在しません。** ONTAP も FSx も、保持期間の満了時にイベントを発行しません。EventBridge Rule で待つ設計は成立しないので、ポーリングします |
| 進行 | Step Functions | 列挙 → 承認待ち → 再判定 → 削除 → 状態確認 → 監査記録。承認待ちを状態として持てる |
| 列挙・削除（ボリューム / Snapshot） | ONTAP REST API | `listExpiredRetention`（実装済み、読み取りのみ）と削除系 |
| 削除（ファイル） | S3 Access Point 経由の `DeleteObject` | オブジェクト単位の削除経路 |
| 通知・監査 | EventBridge Rule + 監査ログ | 削除完了を他系へ配る |

## 守るべき制約（実測に基づく）

### 満了判定は ONTAP の compliance clock で行う

SnapLock は満了をこの時計で決めていて、実時間とずれます。壁時計と比べると、ONTAP が削除を
拒否する対象を「満了済み」として並べてしまい、**時計のずれではなくジョブの故障として見えます**。
`listExpiredRetention` は compliance clock を返し、読めないときは判定せずにそう答えます。
システム時刻への暗黙のフォールバックを入れないでください。早すぎる削除はそこから生まれます。

### 削除の直前に読み直す

保持期間は**延長できます**。列挙時に満了済みだった対象が、承認待ちの間に延長されている
可能性があります。Step Functions は削除ステップの直前に再判定を置きます。列挙結果を信じて
削除する設計にしないでください。

### レスポンスは状態ではない

ボリューム削除は `DELETING` に遷移してから無言で `CREATED` に戻ることがあり、`DeleteVolume`
はエラーを返しません。削除後に**状態確認ステップ**を置き、`Lifecycle` か一覧の再取得で
判定します。フラグを足して再試行しないでください。

### 既定は承認モード

判定を誤ると保持対象が消えます。自動モードは明示的なフラグ（`AutoDeleteOnExpiry=true`）を
要求します。どちらのモードでも削除は監査ログに残します。自動モードでは「誰が」が
「スケジュール」になるため、**根拠にした満了日時の記録が唯一の説明手段**になります。

### ガバナンス上の線引き

これは「満了したものを消す」運用の自動化で、「消してよいか」の判断ではありません。記録保持
義務のある業種では、満了と廃棄可否が一致しないことがあります（訴訟ホールドなど）。ONTAP の
リーガルホールドが掛かっている対象は満了後も削除できないため、実装の挙動としても現れます。

## 実装の段階

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | `listExpiredRetention`（読み取りのみ、compliance clock 基準） | **実装済み**（PR #325）。実機では clock 不在時の応答まで確認 |
| 2 | Step Functions + Scheduler の骨格、承認ゲート、ポータルの承認 UI | 未着手 |
| 3 | 自動モードのフラグ | 未着手 |

段階 2 は承認 UI まで含めます（アカウント所有者の指示）。承認は Step Functions の
`waitForTaskToken` で待ち、ポータルの画面からトークンを返します。

## 承認済みの検証パラメータ

以下はアカウント所有者が値を名指しして承認済みです。再確認は不要です。

| 検証 | 承認された内容 |
|---|---|
| WORM ファイルの確定と削除ブロック | VPC 内に NFS クライアント用 EC2 を 1 台（t3.micro / Amazon Linux 相当）、SnapLock ボリューム 1 本（**保持 5 分**、20 GiB）。保持 5 分なら一巡して削除でき、不可逆な残留を作りません |
| Vscan（Trend Micro ServerProtect） | Windows Server の EC2（t3.medium）1 台。評価ライセンスはベンダーの Web ページから取得 |
| SnapMirror の転送中止 | **検証用の関係をポータルから新規作成**し、必要なデータを投入してから中止を試す。既存の関係は使わない |
| S3 Object Lock | GOVERNANCE / COMPLIANCE ともに保持 **1 日**（C6/C7、実施済み） |
