# Well-Architected Framework — セルフレビュー

> 🌐 言語: **日本語** | [English](../en/well-architected-review.md)

> AWS Well-Architected の 6 つの柱に照らしたポータルアーキテクチャの評価です。

## スコアサマリー

| 柱 | スコア | 主なトレードオフ |
|--------|:---:|---------------|
| 運用上の優秀性 | ⭐⭐⭐⭐ | DemoMode により素早い反復が可能。本番では監視の整備が必要 |
| セキュリティ | ⭐⭐⭐⭐ | AppSync の認可 + Cognito グループ。本番では WAF + SCP が必要 |
| 信頼性 | ⭐⭐⭐ | Lambda + FSx for ONTAP が単一 AZ 構成。マルチ AZ には追加設定が必要 |
| パフォーマンス効率 | ⭐⭐⭐⭐ | ARM64 Lambda + S3 AP の直接アクセス。VPC のコールドスタートはトレードオフ |
| コスト最適化 | ⭐⭐⭐⭐⭐ | 無料利用枠でカバー可能。サーバーレスのため従量課金 |
| 持続可能性 | ⭐⭐⭐⭐ | ARM64（Graviton）、アイドルリソースなし、データローカル処理 |

## 柱ごとの詳細

### 運用上の優秀性

| プラクティス | 状態 | 備考 |
|----------|:---:|-------|
| IaC（CDK/Amplify Gen2） | ✅ | `npm start` による再現可能なデプロイ |
| オブザーバビリティ（ログ） | ✅ | CloudWatch Logs、構造化ログ |
| オブザーバビリティ（メトリクス） | ⚠️ | カスタム CloudWatch メトリクスは未実装 |
| オブザーバビリティ（トレース） | ⚠️ | X-Ray は無効（backend.ts で追加可能） |
| ランブック | ✅ | GETTING-STARTED.md + トラブルシューティング |
| フィーチャーフラグ | ⚠️ | DemoMode のみ。機能単位のトグルはなし |

### セキュリティ

| プラクティス | 状態 | 備考 |
|----------|:---:|-------|
| 認証 | ✅ | Cognito User Pool + 任意の外部 IdP |
| 認可 | ✅ | AppSync のスキーマレベル（グループベース） |
| 保管時の暗号化 | ✅ | FSx for ONTAP の KMS + S3 SSE |
| 転送時の暗号化 | ✅ | HTTPS（AppSync/S3 AP） + 任意の SMB 3.0 |
| シークレット管理 | ✅ | ONTAP 認証情報を Secrets Manager で管理 |
| IAM の最小権限 | ⚠️ | sandbox では `resources: ["*"]`。本番向けガイドを提供 |
| WAF | ❌ | 未設定（本番チェックリストの項目） |
| VPC セキュリティグループ | ⚠️ | sandbox では FSx for ONTAP の SG を共用。本番向けガイドでは分離を推奨 |

### 信頼性

| プラクティス | 状態 | 備考 |
|----------|:---:|-------|
| マルチ AZ | ⚠️ | FSx for ONTAP はマルチ AZ。Lambda は単一サブネット |
| リトライ/バックオフ | ✅ | Step Functions の Retry/Catch |
| ヘルスチェック | ⚠️ | 明示的なヘルスエンドポイントはなし |
| ディザスタリカバリ | ✅ | データは SnapMirror + FlexClone、インフラはスタックの再デプロイ |
| グレースフルデグラデーション | ✅ | DemoMode パターン。ONTAP が切断されてもファイル閲覧は継続可能 |

### パフォーマンス効率

| プラクティス | 状態 | 備考 |
|----------|:---:|-------|
| 適正サイズのコンピュート | ✅ | Lambda ARM64、256MB（ONTAP REST 呼び出しに適したサイズ） |
| キャッシュ | ⚠️ | AppSync のキャッシュは未使用。読み取り高速化には ONTAP の FlexCache |
| 非同期処理 | ✅ | AI ワークロードは Step Functions |
| 直接統合 | ✅ | AppSync → Step Functions（中継 Lambda なし） |

### コスト最適化

| プラクティス | 状態 | 備考 |
|----------|:---:|-------|
| サーバーレス | ✅ | アイドル時のコストはゼロ（Lambda/AppSync/DynamoDB） |
| 無料利用枠の活用 | ✅ | ほとんどのコンポーネントが 12 か月間は無料利用枠の範囲内 |
| 適正サイズの AI モデル | ✅ | コスト重視なら Nova Lite、精度重視なら Claude（設定可能） |
| 過剰プロビジョニングなし | ✅ | EC2 も NAT Gateway も不要 |

### 持続可能性

| プラクティス | 状態 | 備考 |
|----------|:---:|-------|
| Graviton（ARM64） | ✅ | すべての Lambda 関数が ARM64 |
| データのローカリティ | ✅ | ストレージと同一リージョンで処理（クロスリージョンなし） |
| 効率的なプロトコル | ✅ | S3 AP はデータコピーを回避（NAS へのゼロコピーアクセス） |
| アイドルリソースの最小化 | ✅ | サーバーレスのためアイドル状態のコンピュートなし |

## 改善ロードマップ

1. **短期**: X-Ray トレーシング、カスタム CloudWatch メトリクス、WAF の追加
2. **中期**: Lambda のマルチ AZ サブネット化、AppSync キャッシュ、ヘルスエンドポイント
3. **長期**: SnapMirror を用いたマルチリージョン DR、AppConfig によるフィーチャーフラグ
