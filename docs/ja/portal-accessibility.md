# ファイルポータル — アクセシビリティ声明

> 🌐 言語: **日本語** | [English](../en/portal-accessibility.md)

> 実装済みのアクセシビリティ機能と、追加検証に向けたガイダンス。

## 実装済みのアクセシビリティ機能

### キーボード操作

すべての操作対象要素はキーボードで操作できます。

- `Tab` でフォーカス可能な要素間を移動します
- `Enter` / `Space` でボタンとリンクを実行します
- `Escape` でモーダルとドロップダウンを閉じます
- 矢印キーでリスト・メニュー内を移動します
- フォーカスインジケーターはすべての操作対象要素で視認できます

### ARIA マークアップ

| コンポーネント | ARIA の実装 |
|-----------|-------------------|
| AgentChat のメッセージ | `role="log"` と `aria-label` |
| ActionApproval のモーダル | `role="alertdialog"` と `aria-modal="true"` |
| 検索結果 | 結果項目に `role="button"` と `tabIndex` |
| ファイル一覧 | テーブル/グリッドに `aria-label` |
| 言語スイッチャー | `role="radiogroup"` と `aria-checked` |
| モード選択のピル | `role="radio"` と `aria-checked` |
| アラートメッセージ | 適切なライブリージョンを伴う動的コンテンツ |

### スクリーンリーダー対応

- チャットメッセージには発話者の役割（user/assistant/system）を含めています
- ツール実行トレースは `<details>`/`<summary>` で段階的に開示する構造にしています
- ファイル操作の結果にはテキストによる代替表現を含めています
- ステータスバッジには色分けだけでなくアクセシブルなテキストを含めています
- エラーメッセージは支援技術に通知されます

### 視覚的アクセシビリティ

- **配色コントラスト**: WCAG 2.1 AA の最小コントラスト比（テキスト 4.5:1、UI コンポーネント 3:1）を満たします
- **ダーク/ライトモード**: `prefers-color-scheme` メディアクエリに従います
- **文字サイズ**: `rem` 単位を使用し、ブラウザの文字サイズ設定に追随します
- **色のみに依存しない**: ステータス表示は色とアイコン/テキストの両方を使用します

### 国際化（i18n）

- 8 言語に対応し、実行時に切り替えできます
- `navigator.language` から言語を自動判定します
- 言語選択に国旗は使用しません（言語 ≠ 国）
- ユーザーに表示されるテキストはすべて翻訳対象です。技術用語は英語のままとします

## 既知の制約

| 領域 | 制約 | 回避策 |
|------|-----------|-----------|
| PDF プレビュー | 埋め込み PDF ビューアーはスクリーンリーダーに対応しない場合があります | ファイルをダウンロードしてネイティブの PDF リーダーで開きます |
| アスキーアート（構成図） | スクリーンリーダーでは内容を把握できません | alt text で構成を文章で説明しています |
| ドラッグ&ドロップ（画像アップロード） | キーボードによる代替手段があります（ファイル入力ボタン） | 代わりに 📎 ボタンをクリックします |
| リアルタイムの入力中インジケーター | アニメーションが注意をそらす可能性があります | `prefers-reduced-motion` に従います |

## WCAG 2.1 準拠に関する注記

本ポータルは WCAG 2.1 レベル AA のガイドラインに沿ったアクセシビリティ機能を実装しています。ただし、**WCAG 2.1 AA への完全な準拠には、支援技術（スクリーンリーダー、スイッチデバイス、音声操作）を用いた手動テストと、アクセシビリティ専門家によるレビューが必要です**。開発者による認定専門家の正式なアクセシビリティ監査は、まだ実施していません。

アクセシビリティに関する法規制要件がある組織（例: Section 508、JIS X 8341-3、EN 301 549）は、本番デプロイの前に独立したアクセシビリティテストを実施してください。

## 問題の報告

アクセシビリティ上の障壁に遭遇した場合は、以下の手順で報告してください。

1. `accessibility` ラベルを付けて GitHub Issue を作成します
2. 障壁の内容、使用した支援技術、ブラウザ/OS のバージョンを記載します
3. 報告された障壁の修正を優先的に対応します
