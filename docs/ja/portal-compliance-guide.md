# ファイルポータル — セキュリティ・コンプライアンス担当者ガイド

> 🌐 Language: [English](../en/portal-compliance-guide.md) | **日本語** | [한국어](../ko/portal-compliance-guide.md) | [简体中文](../zh-CN/portal-compliance-guide.md) | [繁體中文](../zh-TW/portal-compliance-guide.md) | [Français](../fr/portal-compliance-guide.md) | [Deutsch](../de/portal-compliance-guide.md) | [Español](../es/portal-compliance-guide.md)

セキュリティ担当者、コンプライアンスアナリスト、データ保護担当者向けのガイドです。ストレージ管理を行わず、ポータル経由で規制統制を**検証**するための手順をまとめています。以下のタスクはすべて読み取り専用アクセスで実行でき、`storage-admin` 権限は不要です。

---

## ポータルでの役割

| できること | ポータル上の場所 |
|-----------|---------------|
| ランサムウェア保護ステータスの確認 | サイドバー → 🛡️ ARP/AI |
| スナップショットロックと保持期間の確認 | サイドバー → 🔒 Lock |
| 監査証跡の確認（誰が何にアクセスしたか） | サイドバー → 🔍 Audit Trail |
| PHI ガードレール適用状況の確認 | サイドバー → 📂 All Files（`/dicom/` または `/phi/` に移動） |
| 出力バケットの S3 Object Lock の確認 | サイドバー → 🔒 Lock → S3 Object Lock タブ |
| EMS アラート（ONTAP システムイベント）の閲覧 | Admin → Resources（`storage-admin` でなければ読み取り専用） |

> **注意**: 設定の変更（ロック設定、ARP 状態、エクスポートポリシー）はできません。変更が必要な場合は `storage-admin` ユーザーに依頼してください。

---

## タスク 1: ランサムウェア保護（ARP/AI）の確認

**規制コンテキスト**: FISC、NIST CSF DE.CM-4、ISO 27001 A.12.2

1. サイドバーの **🛡️ ARP/AI** をクリック
2. 監視対象の各ボリュームが緑ステータス（🟢 脅威なし）であることを確認
3. 脅威バッジ（🔴）が表示されている場合は、ボリューム名と検出タイムスタンプを記録
4. **インシデントライフサイクルバッジ** で現在の対応段階を確認:
   - 🔴 検出 — 脅威を特定、封じ込め待ち
   - 🟠 封じ込め済み — 攻撃者のアクセスをブロック、スナップショット保全済み
   - 🟡 調査中 — フォレンジック分析を実施中
   - 🟢 解決済み — インシデントクローズ

**監査人向けエビデンス**: ARP パネルのスクリーンショットを取得し、全ボリュームの保護状態およびアクティブなインシデントバッジとタイムスタンプを記録してください。

---

## タスク 2: スナップショットの改ざん防止（WORM）確認

**規制コンテキスト**: SEC 17a-4、FISC 7 年保持、HIPAA 6 年、SOX 5 年、NARA

1. サイドバーの **🔒 Lock** をクリック
2. 3 つのタブを確認:

### タブ A: ONTAP SnapLock
- ボリュームタイプを確認: **Compliance**（root を含め誰も削除不可）または **Enterprise**（管理者がリリース可能）
- 保持期間がポリシーと一致することを確認:
  - 最小期間 ≥ 規制要件
  - Compliance Clock が初期化済みかつ稼働中

### タブ B: S3 Object Lock
- 出力バケットで Object Lock が有効であることを確認
- モードが適切であることを確認: 規制アーカイブには **Compliance**、AI 出力には **Governance**
- デフォルト保持日数が要件と一致することを確認

### タブ C: 改ざん防止スナップショット
- ロック済みスナップショットテーブルを確認: 名前、作成日時、有効期限
- 有効期限が規制上の保持要件と整合していることを確認:

| 規制 | 必要保持期間 | 期待される有効期限 |
|-----|------------|----------------|
| FISC | 7 年（2,557 日） | 作成日 + 7 年 |
| HIPAA | 6 年（2,192 日） | 作成日 + 6 年 |
| SOX/J-SOX | 5 年（1,825 日） | 作成日 + 5 年 |
| NARA | 3〜75 年（可変） | レコードスケジュールに準拠 |

**監査人向けエビデンス**: 各タブのスクリーンショットを取得し、ロック状態と保持期間を記録してください。

---

## タスク 3: 監査証跡の確認

**規制コンテキスト**: FISC、SOX Section 302/404、HIPAA §164.312(b)、PCI DSS 10.x

1. サイドバーの **🔍 Audit Trail** をクリック
2. S3 Access Point に対する CloudTrail S3 データイベントが表示されます
3. 確認すべき主要フィールド:
   - **誰が**: IAM プリンシパル（Cognito ユーザー ID）
   - **いつ**: イベントタイムスタンプ（UTC）
   - **何を**: API アクション（`GetObject`、`PutObject`、`ListObjectsV2`）
   - **どのファイル**: S3 キー（ファイルパス）
4. 特定のインシデントを調査する場合は、日付範囲またはユーザーでフィルタリング

**監査人向けエビデンス**: レビュー対象期間でフィルタリングした監査証跡をエクスポートまたはスクリーンショットで記録してください。

---

## タスク 4: PHI ガードレールの確認

**規制コンテキスト**: HIPAA §164.502（必要最小限の原則）、45 CFR 164.514

1. サイドバーの **📂 All Files** をクリック
2. `/dicom/`、`/phi/`、`/pii/`、`/hipaa/` のいずれかのフォルダに移動
3. AI 処理ボタンに **🚫 PHI — AI Blocked** と表示されていることを確認
4. ボタンが無効化されている（どのユーザーロールでもクリックできない）ことを確認

**これが意味すること**: これらの保護パスにあるファイルは、外部 AI サービス（Bedrock、Rekognition、Textract、Comprehend）への送信が構造的に防止されています。UI レイヤーでのパスパターンマッチングにより適用され、いかなるユーザーもオーバーライドできません。

**制限事項**: このガードレールはフォルダ命名規則に依存しています。保護パス以外に配置された PHI コンテンツを含むファイルはブロックされません。上流での組織フォルダ構成ポリシーの適用を確認してください。

**監査人向けエビデンス**: `/dicom/` フォルダ内で AI ボタンが無効化されていることを示すスクリーンショットを取得してください。

---

## タスク 5: AI 出力に対する S3 Object Lock の確認

**規制コンテキスト**: SEC 17a-4(f)、CFTC 1.31、FINRA 4511

1. **🔒 Lock** → **S3 Object Lock** タブをクリック
2. 以下を確認:
   - 出力バケットで Object Lock が **有効** であること
   - モードが適切であること: 規制アーカイブには **Compliance**（不変）、AI 出力には **Governance**（権限ありでオーバーライド可能）
   - デフォルト保持期間が保持スケジュールと一致すること
3. Object Lock が未設定の場合は、`storage-admin` ユーザーにエスカレーション

**重要な理由**: AI 処理結果（分類ラベル、抽出テキスト、コンプライアンスレポート）は S3 に保存され、それ自体が規制レコードになる可能性があります。Object Lock により、これらの出力が保持期間中に改変または削除されないことが保証されます。

---

## タスク 6: インシデント対応の確認

ランサムウェアインシデントが検出された場合:

1. **🛡️ ARP/AI** でインシデントバッジの状態を確認
2. 封じ込めが実行されたことを確認:
   - スナップショット取得済み（証拠保全）
   - 疑わしいユーザー/IP をブロック済み
3. **🔍 Audit Trail** で検出タイムスタンプ前後のイベントをフィルタリング
4. タイムラインを文書化: 検出時刻 → 封じ込め時刻 → 調査開始時刻
5. 解決後、インシデントバッジが 🟢 解決済み と表示されていることを確認

**インシデントタイムライン SLA の参考値**:

| フェーズ | 一般的な所要時間 | 自組織の SLA |
|---------|:---:|:---:|
| 検出 → 封じ込め | 5 分未満（自動化） | _____ |
| 封じ込め → 調査開始 | 1 時間未満 | _____ |
| 調査 → 解決 | ケースによる | _____ |

## 実行できない操作（と担当者）

| 操作 | 必要なグループ | 連絡先 |
|-----|:---:|------|
| ARP/AI 状態の変更 | `storage-admin` | ストレージ管理者 |
| スナップショットのロック/解除 | `storage-admin` | ストレージ管理者 |
| S3 Object Lock の設定 | `storage-admin` | ストレージ管理者 |
| ユーザーのブロック/解除（封じ込め） | `storage-admin` | セキュリティ運用 + ストレージ管理者 |
| ボリュームの作成/削除 | `storage-admin` | ストレージ管理者 |
| エクスポートポリシーの変更 | `storage-admin` | ストレージ管理者 |
