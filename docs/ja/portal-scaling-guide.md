# ファイルポータル — スケーリング & キャパシティプランニングガイド

> スケーリング特性、スループット共有、成長見積もりについて。

## コンポーネントのスケーリング概要

| コンポーネント | スケーリング方法 | ダウンタイム | ボトルネックリスク |
|---------|---------|:---:|:---:|
| Lambda (File) | 自動（同時実行数） | なし | 低 |
| Lambda (Admin/VPC) | 自動 | なし | 低 |
| AppSync | 自動 | なし | 低 |
| Cognito | 100 万ユーザーまで | なし | 低 |
| DynamoDB | オンデマンド自動スケーリング | なし | 低 |
| S3 (AP origin) | 自動 | なし | 低 |
| **FSx for ONTAP** | **スループット/ストレージの手動拡張** | **スループット変更時に数分** | **主要** |

ポータルのサーバーレスコンポーネントは自動スケーリングします。唯一のスケーリングボトルネックは FSx for ONTAP のスループット容量です。

---

## スループット共有

S3 AP、NFS、SMB は同じ FSx for ONTAP のスループットバジェットを共有します:

```
FSx for ONTAP スループット（例: 128 MBps）
├── NFS クライアント（EDA ワークステーション、HPC ジョブ）
├── SMB クライアント（Windows ファイル共有）
└── S3 AP（ポータルのファイルブラウジング + AI 処理）
```

### 影響の評価

| ポータル操作 | 通常のスループット | NFS/SMB への影響 |
|------------|---------|---------|
| ディレクトリ一覧 (ListObjectsV2) | < 1 MBps | 無視可能 |
| 単一ファイル読み取り (GetObject) | 1–10 MBps | 無視可能 |
| AI バッチ処理（複数ファイル） | 10–50 MBps | 監視推奨 |
| 大量ダウンロード/リストア | 50+ MBps | 大 — QoS 推奨 |

### 監視

CloudWatch の `ThroughputUtilization` を監視:
- < 70%: 対応不要
- 70–85%: ポータル用ボリュームに QoS ポリシーを検討
- \> 85%: スループットのスケールアップまたはバッチ処理の延期

### 軽減策

1. **QoS ポリシー** — ポータル用ボリュームのスループット上限を設定:
   ```
   ONTAP REST: POST /api/storage/qos/policies
   {
     "name": "portal-limit",
     "fixed": { "max_throughput_mbps": 64 }
   }
   ```

2. **スループット拡張** — FSx for ONTAP の容量を引き上げ:
   - 128 → 256 → 512 → 1024 → 2048 MBps
   - 数分で完了。切替中に短時間の I/O 一時停止あり
   - データ損失やボリュームの再マウントは不要

3. **スケジューリング** — EventBridge Scheduler で AI バッチ処理をオフピーク時間帯に実行

## 成長見積もり

### ユーザー数

| メトリクス | 典型値 | スケーリング懸念 |
|---------|------|:---:|
| 同時ポータル利用者 | 1–50 | なし（Lambda 自動スケーリング） |
| 日次アクティブユーザー | 10–200 | なし（Cognito 無料枠: 50K MAU） |
| AI リクエスト/日 | 10–500 | 大量時は Bedrock スロットリングに注意 |
| 監査クエリ/日 | 1–20 | Athena コスト（軽微） |

### ストレージ

| メトリクス | 計画上の注意点 |
|---------|------|
| ボリュームサイズ | FSx for ONTAP は FlexVol で自動拡張可能（auto-size ポリシーを設定） |
| スナップショット保持 | Tamperproof スナップショットは容量を恒久的に消費 — 予算に組み込む |
| DynamoDB (チャット履歴) | TTL で 90 日後に自動削除。定常状態のサイズは有界 |
| CloudTrail ログ | ライフサイクルポリシーで保持期間を制御。FISC 7 年 = 相応の S3 コスト |

### Bedrock（AI エージェント）

| モデル | リクエスト数/月 | 概算コスト |
|-------|---------|---------|
| Nova Lite | 1,000 | ~$1–10 |
| Nova Lite | 10,000 | ~$10–100 |
| Claude 3.5 Haiku | 1,000 | ~$10–50 |
| Claude 3.5 Haiku | 10,000 | ~$100–500 |

コストは入力コンテキストサイズ（プロンプトに読み込むファイル内容）に大きく依存します。

## 制限とクォータ

| リソース | デフォルト制限 | 引き上げ可 |
|---------|---------|:---:|
| Lambda 同時実行数 | 1,000/リージョン | ✅ (Service Quotas) |
| AppSync リクエスト/秒 | 1,000 | ✅ |
| S3 AP リクエスト/秒 | 5,500 GET, 3,500 PUT/プレフィックス | 自動パーティショニング |
| Bedrock リクエスト/分 | モデル依存 | ✅ (Provisioned Throughput) |
| Cognito サインインレート | 25/秒 | ✅ |
| FSx for ONTAP スループット | ファイルシステム設定による | ✅ (スケールアップ) |

ほとんどのポータルデプロイ（同時 100 ユーザー未満）ではデフォルト制限で十分です。

## 規模別の推奨事項

| チームサイズ | スループット | 推奨事項 |
|---------|---------|---------|
| 1–10 人 | 128 MBps | デフォルト設定。DemoMode でテスト |
| 10–50 人 | 128–256 MBps | NFS 共存時は QoS ポリシーを追加 |
| 50–200 人 | 256–512 MBps | CloudWatch 監視。Bedrock Provisioned Throughput を検討 |
| 200+ 人 | 512+ MBps | Multi-AZ FSx。ポータル専用ボリューム。静的アセットに CloudFront |
