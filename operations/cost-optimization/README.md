# OPS5: Cost Optimization — FinOps 統合コスト最適化

🌐 **Language / 言語**: 日本語 | [English](README.en.md)

## 概要

FSx for ONTAP のコスト構成を分解・可視化し、単位経済 ($/GB)、成長予測、
トップコストドライバー分析、AI 推奨を提供する FinOps パターン。

**コスト構成要素**: SSD容量 + Capacity Pool + スループット + バックアップ

## 出力

### CloudWatch カスタムメトリクス (Namespace: `FSxOps`)

| メトリクス | 単位 | 意味 |
|-----------|:----:|------|
| `MonthlyTotalCostUSD` | None | 構成要素を合算した月額 |
| `CostPerGBUSD` | None | 単位経済 ($/GB/月) |
| `ProjectedCost` | None | 成長率を当てはめた 3 か月後の見込み |

### S3 レポート

`data_classification` フィールドを含みます（既定 `INTERNAL`、環境変数 `DATA_CLASSIFICATION` で上書き可）。

## 成功指標

| 成果 | 指標 | 目標 | 人による確認 |
|------|------|------|:-----------:|
| コスト構成の可視化 | 内訳を取得できた構成要素の割合 | 100% | — |
| 単位経済の追跡 | `CostPerGBUSD` の推移 | 増加傾向でない | ✅ |
| 予算超過の早期検知 | 予測と実績の乖離 | 20% 以内 | ✅ |
| 削減機会の特定 | トップコストドライバーの特定件数 | 1 件以上 | ✅ |
| 実行の安定性 | ワークフロー成功率 | > 99% | — |

> **予測の性質**: 3 か月予測は月次成長率 **5% の固定値**をベースラインとして当てはめた単純な複利計算です（`functions/analyze/handler.py`）。実測の成長率に基づく予測ではないため、傾向の把握には使えますが、予算策定の根拠にはなりません。組織の実績成長率で置き換えて使ってください。

## Governance Note

このパターンは**読み取りと試算のみ**を行い、リソースの変更や購入は実行しません。

算出額は **AWS の請求データではありません**。FSx API から取得した構成値に単価を掛けた見積りです。実際の請求額は、リージョン、割引契約、Savings Plans、データ転送、その他のサービス利用によって異なります。**請求の照合には AWS Cost Explorer と請求書を使ってください。**

さらに、構成要素ごとに精度が異なります。

| 構成要素 | 取得元 | 精度 |
|---------|-------|------|
| SSD 容量 | FSx API の `StorageCapacity` | 構成値（正確） |
| スループット | FSx API の `ThroughputCapacity` | 構成値（正確） |
| Capacity Pool | **SSD 容量 × 0.5 の推測値** | 実使用量ではない |
| バックアップ | **SSD 容量 × 0.2 の推測値** | 実使用量ではない |

Capacity Pool とバックアップの実使用量は取得していません（`functions/collect/handler.py`）。この 2 要素を含む金額は実測ではなく係数計算であり、実際の階層化状況やバックアップ保持量とは無関係です。内訳の構成比を見る用途では、この点を踏まえて解釈してください。

単価はテンプレートのパラメータとして与えるため、AWS の価格改定に自動追従しません。定期的な見直しが必要です。

> **財務判断に関する補足**: 本パターンの出力は技術的なコスト構成の可視化であり、財務上の助言や予算コミットメントではありません。調達や予算計画の判断は、組織の財務部門の確認を経てください。
