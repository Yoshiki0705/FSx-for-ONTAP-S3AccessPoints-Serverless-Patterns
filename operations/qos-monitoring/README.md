# OPS6: QoS Monitoring — QoS ポリシー監視

🌐 **Language / 言語**: 日本語 | [English](README.en.md)

## 概要

FSx for ONTAP の QoS (Quality of Service) ポリシーの遵守状況を監視し、
帯域争奪 (noisy-neighbor) リスクの検出とワークロード分離推奨を提供するパターン。

## 検出項目

| 検出 | 重要度 | 説明 |
|------|:------:|------|
| QoS ポリシー未割当てボリューム | Medium | ポリシーなしは帯域無制限 → 他ワークロードに影響 |
| スループット制限なしポリシー | Low | max_throughput 未設定 → バースト時に帯域争奪 |
| 1ポリシーに多数ボリューム | Low | 10+ ボリュームで共有 → ポリシー分割推奨 |

## 出力

### CloudWatch カスタムメトリクス (Namespace: `FSxOps`)

| メトリクス | 単位 | 意味 |
|-----------|:----:|------|
| `VolumesWithoutQoS` | Count | QoS ポリシー未割り当てのボリューム数 |
| `QoSPoliciesWithLimits` | Count | スループット上限が設定済みのポリシー数 |
| `QoSRecommendationCount` | Count | 生成された推奨の件数 |

### S3 レポート

`data_classification` フィールドを含みます（既定 `INTERNAL`、環境変数 `DATA_CLASSIFICATION` で上書き可）。ポリシー名とボリューム名は含みますが、ファイル内容は含みません。

## 成功指標

| 成果 | 指標 | 目標 | 人による確認 |
|------|------|------|:-----------:|
| 帯域争奪リスクの低減 | `VolumesWithoutQoS` | 0 に近づく | ✅ |
| ポリシー設定の網羅 | `QoSPoliciesWithLimits` / 総ポリシー数 | 100% | ✅ |
| ワークロード分離 | 1 ポリシーあたりのボリューム数 | 10 以下 | ✅ |
| 検出の即応性 | 未割り当て発生から検出までの時間 | スケジュール間隔以内 | — |
| 実行の安定性 | ワークフロー成功率 | > 99% | — |

> **閾値の根拠**: 「1 ポリシーあたり 10 ボリューム」はワークロード分離の目安として設定した値で、性能試験に基づく限界値ではありません。実際に許容できる集約度はワークロードの I/O 特性に依存します。

```bash
python3 -m pytest operations/qos-monitoring/tests/ -v

```

## Governance Note

このパターンは**読み取りと推奨のみ**を行い、QoS ポリシーの作成・変更・割り当ては実行しません。

QoS の上限設定は誤ると本番ワークロードを意図せず絞ります。特に「スループット制限なし → 上限設定」の推奨は、上限値そのものを提示しません。適切な値はワークロードのピーク I/O を実測してから決めてください。上限を低く設定すると、障害ではなく設定に起因する性能低下が発生し、原因の切り分けが難しくなります。

「QoS 未割り当て」の検出は、そのボリュームが**問題である**ことを意味しません。単一ワークロード専有のファイルシステムでは、ポリシーを付けない運用が妥当な場合もあります。推奨は検討の起点として扱ってください。

> **性能に関する補足**: 本パターンの出力は QoS 設定の構成情報に基づく静的な分析です。実際の帯域争奪の発生有無は、ONTAP の性能統計や CloudWatch のスループットメトリクスで確認する必要があります。
