# OPS2: Storage Efficiency — 重複排除/圧縮効率

🌐 **Language / 言語**: 日本語 | [English](README.en.md)

## 概要

FSx for ONTAP の重複排除 (deduplication) と圧縮 (compression) の効率比を追跡し、
低効率ボリュームに有効化・チューニング推奨を提供するパターン。

## 推奨ロジック

| 状態 | 推奨 |
|------|------|
| dedupe=off, compression=off | 両方有効化 (推定 2:1 効率) |
| 有効だが ratio < MinEfficiencyRatio | データパターンの確認を推奨 |
| 高効率 (ratio ≥ 1.5) | 推奨なし |

## 出力

### CloudWatch カスタムメトリクス (Namespace: `FSxOps`)

| メトリクス | 単位 | 意味 |
|-----------|:----:|------|
| `AvgEfficiencyRatio` | None | 論理容量 / 物理容量の平均比 |
| `TotalDedupSavingsGB` | Gigabytes | 重複排除 + 圧縮による削減量 |
| `EfficiencyRecommendationCount` | Count | 生成された推奨の件数 |

### S3 レポート

`data_classification` フィールドを含みます（既定 `INTERNAL`、環境変数 `DATA_CLASSIFICATION` で上書き可）。効率比とボリューム構成は運用メタデータであり、ファイル内容は含みません。

## 成功指標

| 成果 | 指標 | 目標 | 人による確認 |
|------|------|------|:-----------:|
| ストレージコスト削減 | 削減量 (`TotalDedupSavingsGB`) | 有効化前比で増加 | ✅ |
| 効率の可視化 | 効率比を取得できたボリュームの割合 | 100% | — |
| 推奨の妥当性 | 推奨のうち採用されたものの割合 | > 60% | ✅ |
| 実行の安定性 | ワークフロー成功率 | > 99% | — |
| 検出の即応性 | 効率低下から検出までの時間 | スケジュール間隔以内 | — |

> **目標値の根拠**: いずれも運用上の目安であり、ベンチマーク値ではありません。データパターンによって達成可能な効率比は大きく変わるため、初回実行の結果を基準線として調整してください。

## テスト

```bash
python3 -m pytest operations/storage-efficiency/tests/ -v
make test-ops2
```

## Governance Note

このパターンは**読み取りと推奨のみ**を行い、重複排除や圧縮の設定変更は実行しません。推奨の適用は運用担当者の判断と作業に委ねられます。

重複排除と圧縮の有効化は、既存データに対しては次のバックグラウンド処理まで反映されません。有効化直後に効率比が改善しないのは正常な挙動です。また、圧縮は CPU を消費するため、レイテンシに敏感なワークロードでは有効化の影響をテスト環境で確認してください。

推定効率比 2:1 は一般的な目安であり、暗号化済みデータや既に圧縮されたメディアファイルではほとんど効果が出ません。推奨に含まれる削減見込みは確約ではありません。

> **コンプライアンスに関する補足**: 本パターンの出力は運用改善のための技術的な示唆であり、契約上のコスト削減保証や監査証跡としての性質を持ちません。規制対応の判断に用いる場合は、組織のコンプライアンス部門の確認を経てください。
