# Pattern directories whose tests are run, one per line.
#
# Read by BOTH the Makefile `test` target and .github/workflows/ci.yml, because
# those two kept their own hand-maintained lists and drifted apart. CI listed 37
# directories, the Makefile reached 16, and 13 directories with passing tests —
# about 790 tests — were in neither, so they never executed anywhere. Adding a
# pattern meant remembering two places, and forgetting one was silent.
#
# Each directory gets its own pytest process. Many patterns ship a functions/
# package with colliding module names (functions.discovery in every one of them),
# so a single combined invocation raises ModuleNotFoundError once sys.modules
# caches the first pattern's package. See AGENTS.md, "from functions.xxx import
# collision in batch test runs".
#
# Excluded on purpose:
#   solutions/event-driven/fpolicy   tests/ holds only an empty __init__.py, so
#                                    pytest collects nothing and exits 5, which
#                                    fails the loop under `set -e`. Add it here
#                                    once it has a test.
#   infrastructure/knfsd-file-cache  5 test files that require a deployed cache
#                                    and a reachable FSx for ONTAP file system:
#                                    9 fail and 7 skip against no environment.
#                                    Same category as tests/e2e and tests/load.
#   tests/e2e, tests/load            require deployed stacks (see AGENTS.md).
#   solutions/amplify-portal/tests   directory exists but holds no test file.
#
# scripts/tests/test_test_dir_coverage.py reconciles this file against the tests/
# directories that actually exist, so an addition to the tree that is not listed
# here — or an exclusion that is not stated above — fails rather than going quiet.
#
# `shared/`, `scripts/` and `operations/` as a whole are invoked separately by the
# Makefile and by CI; the per-pattern operations/ entries below are the individual
# OPS patterns.
#
# To check this file still matches reality:
#   ls -d solutions/*/*/tests operations/*/tests | sed 's:/tests$::' | sort
#
# The amplify-portal entries below are one level deeper than the rest, because the
# portal keeps a tests/ directory per Lambda rather than per pattern. They are

# against regression. The glob in the check above does not reach them — use
#   ls -d solutions/amplify-portal/functions/*/tests | sed 's:/tests$::'

# module as `handler` or `index`, names that fourteen and nine of these directories

# own and `scripts/check_test_module_names.py` refuses the pattern — so the whole
# tree now passes in one invocation. Isolation stays for the reason at the top of
